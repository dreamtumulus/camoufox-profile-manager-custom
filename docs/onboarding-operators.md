# 上号员与分配（多用户上号）

共享服务器（`python -m camoufox_pm.onboarding_server`）是分配关系的唯一来源：管理员
维护上号员、出口 IP 池和邮箱；上号员在自己电脑上登录后，只收到分配给自己的邮箱和 IP。

## 角色

| 身份 | 凭据 | 能做什么 |
|---|---|---|
| 管理员 | `CPM_ONBOARDING_SERVER_TOKEN`（上号页“共享与接口配置”里保存） | 全部旧功能，加上“上号员与分配” |
| 上号员 | 管理员创建的账号和密码 | 只看到并操作分配给自己的邮箱、IP 和上号记录 |

上号员登录后拿到的是 30 天有效的个人令牌（本地加密保存）。管理员重置密码或停用账号会让
该上号员的所有登录立刻失效。

## 管理员流程

1. 在 1dayApi 导入代理（和以前一样）。
2. 上号页 →“上号员与分配”→ 创建上号员。
3. “出口 IP 池”：选择节点，把同一批代理（`socks5://user:pass@host:port`，每行一个）
   粘贴进来。服务器向 1dayApi 读取该节点的可用代理，按 `host:port` 对上平台的 proxyId
   和出口 IP；平台里没有的行会列出来，不保存。代理密码在服务器上加密存储。
4. 勾选 IP 分配给上号员（也可以导入时直接指定）。
5. “邮箱分配”：选择上号员和组织，批量粘贴邮箱。每个邮箱自动配到该上号员名下空位最多的
   IP（每个 IP 的名额即导入时的“可上邮箱数”，默认 2）。放不下的邮箱会列出来，不保存。

> 1dayApi 的接口不返回代理账号密码，所以第 3 步需要再粘贴一次代理列表。

## 上号员流程

打开上号页 → 输入账号密码登录 → 任务列表里每个邮箱已经配好出口 IP → “开始上号”打开
窗口并预填邮箱 → 登录 Claude 后自动提取 SK →“提交 SK”。不需要在本地代理库里添加任何代理。

安装包可通过环境变量 `CPM_ONBOARDING_SERVER_URL` 预置服务器地址，上号员就只需填账号密码。

## 服务器保证

- 邮箱用哪个 IP 由服务器根据分配决定，客户端不能指定。
- 每次调用都校验归属；别人的记录一律返回“不存在”。
- SK 由服务器提交到平台，平台登录密钥不会下发到上号员电脑。
- 已提交的邮箱不能重复上号，也不能被收回。
- 登录、开窗口、提交、导入、分配都记入审计日志（管理员概览里可见）。
- 同一账号 15 分钟内连续输错 10 次密码会被暂时拒绝登录。

旧的共享令牌接口（`/v1/state`、`/v1/accounts`、`/v1/sessions` 等）保持不变，仅管理员可用。
